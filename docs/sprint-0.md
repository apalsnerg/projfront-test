<h2>2. Tekniska val</h2>

Frontend-ramverk: React
- React är användarvänligt då det är väldokumenterat och populärt, vilken innebär att det finns många resurser och redan svarade frågor och beskrivningar på lösta problem
- React är funktionsrikt och är effektivt och har hög prestanda när det kommer till live-manipulation av DOM (vilket hela applikationen skall baseras på)
- Eftersom det är rekommenderat kommer det vara lättare att följa med i exempel och att be om hjälp
- Väldigt populärt på marknaden och utgör grunden för flera andra vanliga ramverk (t.ex. Next.js)

Kodeditor-bibliotek: Monaco
- Välbekant för VSCode-användare
- Populärt på marknaden
- Funktionsrikt (intellisense, diff editor, mm)

Övriga tekniska val
CSS-Ramverk: Tailwind CSS
- Populärt på marknaden
- Tailwind har lättförståelig syntax och är modulärt
- Att lära sig ramverk är värdeful erfarenhet på marknaden

Ikon-biblotek: Font Awesome och Flaticon
- Många ikoner (64.000+ resp. 18 miljoner)
- Gratis och användarvänliga
- Font Awesome har inbyggd attribuering (Flaticon kräver att det finns på sidan)

<h2>4. Gruppens arbetssätt</h2>

Hur planerar ni att kommunicera inom gruppen?
- Vi tänker använda WhatsApp för enkel chatt och kommunikation, samt för snabb avstämning med varandra eller rådfrågning.
- Varje vecka (minst en gång i veckan) skall vi ha scrum-möte via Zoom för reflektion, diskussion, och planering

Hur ska ni fördela arbete?
- Initiellt tänker vi prova att fördela arbetet ganska jämt, circa 20 timmar/vecka var (eller vad som verkar rättvist efter estimering), så att alla får dra sitt strå till stacken. Resterande 20% tänker vi lämna "free for all" så att de med tid över eller som känner för att ta sig an en särskild uppgift kan ta sig an dem. Om detta visar sig inte fungera så kommer vi analysera produktivitetsnivåer och diskutera ett nytt upplägg som alla är bekväma med.
- Vi tänker också prova på roller med Birk som Product Owner och Jonas som Scrum Master. Om detta inte fungerar väl så byter vi tillbaka till ett mer flexibelt alla gör allt-system. Vi har också tankar på att rotera roller så att fler får prova på att vara PO och SM, men det är inte spikat.

Har ni en plan för om samarbetet inte fungerar som tänkt - har ni ett kontrakt för hur samarbetet ska gå till?
- Vi kom inte riktigt överens om ett konkret samarbetskontrakt - men vi tänker väl att om någon halkar efter så axlar de andra dennes börda. Vi har förståelse för att livet kan hända och är villiga att hjälpa varandra. Den som hjälper idag kanske behöver hjälp imorgon, så det blir nog jämt upp i slutändan.

Planeringsverktyg: Vi har valt att använda Trello av flera anledningar:
- UI:en är tydlig och lättförståelig
- Flödet för krav => user story => fördelad task => review är extremt smidigt
- Varje tavla har stark sammankoppling med varandra och kort kan enkelt flyttas mellan dem
- Organisationskapaciteten är väldigt stark
- Det är väldigt lätt att fördela uppgifter eller att byta dem sinsemellan
